Site audit

I tested 19 page types in English and Spanish in both themes, crawled all 144 live URLs, measured how much of every CSS and script file each page actually uses, and checked the asset library, pages, site code and the repo. The site works: no errors from our code, every page loads, the header, footer and booking work. The issues are weight, search visibility, dead links behind the booking buttons, and leftovers from the old template and from our own fix rounds.

Fix first

These affect visitors or search results today.

  • Critical

    robots.txt blocks the whole blog

    The live robots.txt disallows /blog, /post/ and /blog-category/, so Google is told not to read any of the 45 English posts or the category pages, even though they are in the sitemap. The Spanish copies are not blocked. It also lists dead paths from the old site (/sase-studies, /about-us, /for-clients/…) and blocks /thank-you, which is still in the sitemap.

    Webflow: Site settings → SEO → robots.txt. Replace with User-agent: *, Disallow: /log-in, Disallow: /thank-you, the sitemap line, and nothing else. Then turn off "include in sitemap" on Thank You.

    Who: you, in Site settings (not reachable through the API)Effort: 5 minutes
  • Critical

    "Book a call" links point to deleted calendars

    Every booking button has a fallback link to a GoHighLevel calendar. Five of the six calendar IDs used across the site return 404 (header CTA 17jl7…, footer l4rv…, Services/CRM 3blt…, Our Team o811…, Contact usaN…). A normal click still opens the booking pop-up, so most visitors never notice. But anyone who opens the link in a new tab, long-presses it on a phone, or clicks before the scripts load lands on a dead page, and search engines see broken links.

    Point every booking link at /book-discovery-call (our own page, which runs the same pop-up) and keep the pop-up behaviour. I can do this in one pass across the page embeds and the Spanish bundle.

    Who: meEffort: smallLooks: unchanged
  • High

    Spanish pages ship English HTML

    On /es/* the page source is the English page. A 167 KB script (kd-es.js) then swaps in the Spanish header, body and footer, while the page is hidden for up to 3 seconds. Search engines that do not run scripts index English text under Spanish URLs. The bundle dates from 16 Nov, so later content fixes reach Spanish visitors only through small runtime patches.

    Rebuild the Spanish bundle from today's sources, so the patches are no longer needed, and split it per page (about 10–25 KB each instead of 167 KB on every Spanish page). Longer term, put the Spanish text into the Webflow localization itself so it is in the page source.

    Who: meEffort: mediumLooks: unchanged
  • High

    Contact webhook is public in browser code

    The site-wide booking config (built in the other chat) puts the GoHighLevel inbound webhook URL for the contact form in the page source. Anyone can copy it and post fake leads straight into the CRM, skipping the form's checks.

    Send the contact form through the same Webflow Cloud app the booking already uses (/api/booking/…), which keeps the webhook server-side and lets it rate-limit.

    Who: the booking chat (it owns the site-level code)
  • Medium

    Knowledge base: broken embeds and empty SEO

    The knowledge base page carries four hidden booking iframes from the old template. Three of them point to deleted calendars, and the calendar script loads four times, adding about 2 MB and 90+ requests. Article and category pages have empty meta descriptions, because their template fields render blank, and the page has a second hidden <h1>.

    Remove the hidden booking blocks from the members template, fix the two SEO description templates, and drop the hidden heading.

    Who: me (Designer elements) Effort: small

Our code: cleanup without changing the look

Our CSS and JS were built by appending each fix round to the previous file. That works, but it leaves rules that are overridden later and features that no longer exist.

Stylesheet (81 KB source, 68 KB hosted)

  • 49 selectors defined two or three times in the same scope; the later one wins (for example .hud::before ×3, .nav__trigger ×3, the headings ×2).
  • Dead blocks: the old lifecycle diagram (~20 rules), the old contact form (~35), the old booking embed, dialog and paused calendar CTA (~20), and old blog layout pieces (.cats, .post-feature, .guides).
  • 17 !important overrides that mostly exist to beat our own earlier rules.
  • Result after consolidation: one ordered file, about 45 KB instead of 68 KB.

Script (61 KB)

  • Dead: the generic tabs handler, the old circuit diagram, the old form handler and the booking-embed helpers, all replaced since.
  • Runtime patches that edit content after load: the hero eyebrow, Ahmed's title, removing the footer AI Suite link, inserting the map. They work, but the text should live in the page itself.
  • The Title Case pass walks every text node on load and again after load. Keep it; once the copy is in Title Case in the source it becomes a safety net only.
  • Result: about 50 KB, with fewer moving parts.

Page structure

  • The header and footer are copied into every page's embeds (16 site pages, 4 member pages, the Spanish bundle). A menu change means about 20 edits. A single shared component, or one hosted partial, makes it one edit.
  • Blog, post, category and home pages still hold the old template's page wrapper, set to hidden. It is still downloaded and still pulls in the old styles. Removing it also lets the template stylesheet clean-up go further.
  • Blog thumbnails are 900px wide but shown at 220px. A 480px set would save about 400 KB on the blog and category pages. These are our assets, so I can regenerate them.
  • About 20 images on the home page (the reviews widget) have no width or height, so the layout shifts as they load.

How I would verify "no visual change": full-page screenshots of every page type in both languages, both themes, desktop and phone, before and after, compared pixel by pixel before publishing.

Working rules from here

  • Build hosted files from source in one step, never by appending to the last file. Delete the previous version when a new one goes live.
  • Put copy changes in the page content, not in scripts that rewrite text after load. Runtime patches are for emergencies and get folded back in the next round.
  • Size images for how they're shown: thumbnails at 2× their display width, with width and height set.
  • Load third-party widgets (reviews, calendars, maps) when they come into view, not on page load.
  • Keep the regression check we already use (every page type, both languages, both themes, no errors, fixed panel heights) and run it before every live publish.
